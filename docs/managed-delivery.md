# Managed delivery handoff

Project Alpha's Managed Delivery provider delegates delivery provisioning to a configured external delivery service, such as the LTDS Ops Worker. Project Alpha does not connect this provider directly to object storage and does not store storage credentials, object paths, client-facing URLs, bearer tokens, or recipient email addresses. The Dropbox, Google Drive, S3, and R2 link resolvers remain available to standalone/open-source installations.

The provider is disabled by default. Configure the external delivery service's exact HTTPS URL ending in `/api/internal/project-alpha/delivery-intents` and select an enabled custom integration profile under **Settings → Links & Storage**. For LTDS this is `https://incoming.ledgetopdroneservices.com/api/internal/project-alpha/delivery-intents`, not the staff Ops hostname, and the profile is an External Ops Access integration. The selected profile supplies its existing encrypted HMAC secret and optional Access headers. **Test delivery capability** signs a non-mutating request to the derived `/preflight` route and works before the local provider is enabled.

Managed Delivery and the standalone direct-R2 resolver cannot be enabled together. A rejected dual-enable save does not erase stored standalone R2 credentials.

Initial delivery is deliberately manual: an operator selects a content scope and one active Client Portal principal, then chooses **Generate / Send Delivery**. Client Portal is preselected. Guest/public access appears only when the global guest switch is enabled and the operator explicitly chooses it; a portal failure never falls back to guest access. Ops owns guest expiry policy: a missing expiry means 30 days and the maximum is 90 days. An explicit expiry must be more than six minutes in the future, preserving the receiver's five-minute minimum plus dispatch margin. No delivery is generated by invoice finalization.

Every request is written to `managed_delivery_intent_outbox` before transmission. Its integration profile, machine destination, application key, signing key ID/secret epoch hash, timeout, and retry limit are pinned without copying any secret. Retries therefore cannot silently move to a newly configured destination or key; they fail closed if that exact profile/key epoch is no longer available. The one-minute cron sender has bounded batches, a bounded aggregate runtime, claim leases, retry/backoff, and dead-letter state. A successful response must be exact HTTP 202 JSON `{ "receiptId": "…", "status": "accepted" }`. Only the neutral receipt and status are retained. The status table exposes revocation for accepted deliveries; Project Alpha signs `/delivery-intents/revoke` and marks the original local record revoked only after Ops accepts that request. Revocation inherits the accepted provision's receiver profile, destination, and application key, while selecting the current signing key for that same profile at revoke creation and pinning that new epoch for retries. Current global settings cannot reroute or block explicit revocation recovery. A dead-lettered revocation has an explicit audited **Retry revocation** action that reuses the same durable request and pinned contract.

The normative LF-pinned wire fixture is `tests/fixtures/project-alpha-delivery-intent-v1.json`, SHA-256 `f16d540bcfbcf4c77c356fc37e2c046a23a473ebec701d526e3b8d45f38c90e8`. It contains exact preflight, portal, guest, revocation, canonical, signature, and response bytes and must be mirrored unchanged by the Ops implementation.

## Deployment evidence

Before enabling the provider:

1. Apply `database/migrations/0069_managed_delivery_intents.sql` and record the successful migration evidence.
2. Confirm `managed_delivery_intent_outbox` includes the pinned-contract columns and `integration_profile_id` foreign key.
3. Confirm the four default-off values with:

   ```sql
   SELECT config_key, config_value
   FROM app_config
   WHERE organization_id = 0
     AND config_key IN (
       'managed_delivery_enabled',
       'managed_delivery_intent_url',
       'managed_delivery_profile_id',
       'managed_delivery_guest_links_enabled'
     )
   ORDER BY config_key;
   ```

   The expected values are exactly:

   - `managed_delivery_enabled = 0`
   - `managed_delivery_intent_url = ''`
   - `managed_delivery_profile_id = 0`
   - `managed_delivery_guest_links_enabled = 0`

The required Ops routes are:

- `POST /api/internal/project-alpha/delivery-intents/preflight`
- `POST /api/internal/project-alpha/delivery-intents`
- `POST /api/internal/project-alpha/delivery-intents/revoke`

All three use the Portal Projection path-bound signing envelope. Redirects, non-success status codes, malformed or oversized bodies, and response-shape drift fail closed.
