# Invoice Auto-Email & Extra Charges Implementation Summary

**Date:** November 12, 2025  
**Branch:** dev  
**Status:** Ready for Integration Testing

---

## Overview

This implementation adds three major features to Project-Alpha:

1. **Invoice Auto-Email Settings** — Users can toggle automatic email reminders for invoices (due-in-7 and weekly overdue)
2. **Notification Management UI** — Admin interface to view and audit sent invoice reminders
3. **Extra Charges on Invoices** — Allow adding line items to invoices beyond contract scope, marked distinctly in PDFs

---

## Feature 1: Invoice Auto-Email Settings

### Rationale
Automate customer notifications for invoices without manual intervention, with configurable triggers:
- **Due-in-7 reminder**: Send once per invoice when it enters the 7-day-before-due window
- **Overdue weekly reminder**: Send weekly for any overdue invoices, max once per 7 days per invoice

### Files Modified

#### `src/config/app.php`
- Added two new config defaults:
  - `invoice_auto_send_due_7days` (default: 0)
  - `invoice_auto_send_overdue_weekly` (default: 0)

#### `src/controllers/settings_handler.php`
- Added setting persistence for the two new invoice email toggles
- Saves checkbox state (0 or 1) to settings.json

#### `src/views/pages/settings.php`
- Added "Automatic Invoice Emails" fieldset in the Invoices tab
- Two checkboxes for due-7 and overdue-weekly options
- User-friendly labels describing each reminder type

#### `database/migrations/000_all.sql`
- Added `invoice_notifications` table to track sent reminders:
  ```sql
  CREATE TABLE IF NOT EXISTS invoice_notifications (
    id INT AUTO_INCREMENT PRIMARY KEY,
    invoice_id INT NOT NULL,
    type VARCHAR(32) NOT NULL,  -- 'due_7' or 'overdue_weekly'
    sent_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_invnot_invoice (invoice_id),
    INDEX idx_invnot_type (type),
    CONSTRAINT fk_invnot_invoice FOREIGN KEY (invoice_id) REFERENCES invoices(id) ON DELETE CASCADE
  ) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
  ```

### Cron Implementation

#### `src/cron/generate_recurring_invoices.php`
- Enhanced to send invoice reminders after generating recurring invoices
- Two reminder loops:
  1. **Due-in-7 reminders**: Finds invoices due in exactly 7 days, checks `invoice_notifications` to send once per invoice
  2. **Overdue weekly reminders**: Finds overdue unpaid invoices, enforces 7-day minimum between reminders via `sent_at` timestamp check
- Creates public_links for each reminder email with 7-day expiry (configurable via `documents_valid_days` setting)
- Uses existing SMTP config and `mailer_send()` utility for email delivery
- Logs all actions via `logger_info()` for audit trail

#### `src/cron/send_invoice_reminders.php` (NEW)
- Standalone cron script (~260 lines) that can run independently
- Mirrors logic from `generate_recurring_invoices.php` but focused solely on reminders
- Can be scheduled separately for finer-grained control
- Includes:
  - SMTP config decryption (handles both encrypted password_enc and plaintext password)
  - Due-7 and overdue-weekly reminder loops
  - Public link generation
  - Notification recording to avoid duplicates
  - Settings.json update with `reminders_last_run` timestamp
  - Comprehensive error handling and logging

### How It Works

1. **User enables setting** via Settings → Invoices tab
2. **Cron runs** (daily or as scheduled):
   - Queries unpaid invoices by due date
   - Checks `invoice_notifications` table to prevent duplicate sends
   - Creates time-limited public link for client invoice access
   - Sends email via SMTP using client's email address
   - Records notification in `invoice_notifications` with type and timestamp
3. **Weekly cadence enforcement**: For overdue reminders, only sends if last notification was >7 days ago (prevents spamming)

## Feature 3: Extra Charges on Invoices

### Rationale
Allow users to bill for work exceeding the contract scope while keeping contract items immutable for audit and reference. Extra charges are visually distinct in PDFs and can be offset with discounts.

### Database Schema Changes

#### `database/migrations/000_all.sql`
- Modified `invoice_items` table to add:
  ```sql
  is_extra_charge TINYINT(1) NOT NULL DEFAULT 0,
  INDEX idx_invoice_items_extra (is_extra_charge)
  ```
- Allows tracking which line items are contract-based vs. user-added extras

### Files Modified

#### `src/controllers/invoice/invoices_update.php`
- Refactored to preserve contract items (is_extra_charge=0) and only update extras
- Logic:
  1. Fetch existing items to preserve contract items
  2. Process extra charges from form (new and updated)
  3. Delete only items marked `is_extra_charge=1`
  4. Insert new extra charges with `is_extra_charge=1` flag
  5. Recalculate subtotal including contract items + extras
  6. Apply discount and tax calculations
- Uses transactions for data consistency

#### `src/views/pages/invoice/invoices-edit.php`
- **Contract Items Section** (unchanged but clarified):
  - Read-only display of contract items from linked contract
  - Note: "To change items, modify the contract and apply a discount if needed"
  
- **New Extra Charges Section**:
  - Yellow-highlighted section (background: #fffbeb, border: #fbbf24)
  - Displays existing extra charges in editable grid (if any):
    - Description (text input)
    - Quantity (number input)
    - Unit Price (number input)
    - Remove button for each row
  - "+ Add Extra Charge" button to add rows dynamically
  - JavaScript function `addExtraCharge()` appends new row to form

- **JavaScript Functions**:
  - `addExtraCharge()`: Creates new extra charge row with input fields and remove button
  - `recalcInv()`: Recalculates totals when extra charges change (empty stub for now; server handles actual calc)
  - Attaches event listeners to discount and tax inputs for real-time UI updates

#### `src/views/pages/invoice/invoice-print.php`
- Modified to fetch `is_extra_charge` flag from invoice_items
- Renders extra charges with:
  - Yellow background row (#fffbeb)
  - Badge label "Extra Charge" in yellow (#fbbf24 background, #92400e text)
  - Same columns as contract items (description, qty, unit price, line total)
- Non-extra items render normally without highlighting or badge

### Workflow

1. **User creates invoice** from contract (contract items auto-populated as is_extra_charge=0)
2. **User edits invoice** and adds extra charges (new items with is_extra_charge=1)
3. **Extra charges displayed** in yellow section during edit for clarity
4. **PDF rendering** shows extra charges with yellow background and "Extra Charge" badge
5. **Discounts/Tax** apply to full subtotal (contract + extras)

### Calculations

- **Subtotal** = Sum of (contract items + extra charges)
- **Discount** = Applied to full subtotal (percent or fixed)
- **Tax** = Applied to (subtotal - discount)
- **Total** = (subtotal - discount) + tax

- `invoice_items.is_extra_charge` (track extra charges)

### How to Apply

**Option 1: Full re-initialization**
```bash
mysql -u root -p project_alpha < database/migrations/000_all.sql
```

**Option 2: Selective ALTER**
```sql
USE project_alpha;

-- Add invoice_notifications table
CREATE TABLE IF NOT EXISTS invoice_notifications (
  id INT AUTO_INCREMENT PRIMARY KEY,
```

## Configuration & Dependencies

### Required Settings (in settings.json or defaults)
- `invoice_auto_send_due_7days` (0 or 1) — Enable due-in-7 reminders
- `invoice_auto_send_overdue_weekly` (0 or 1) — Enable overdue weekly reminders
- `documents_valid_days` (default: 7) — Public link expiry for invoice reminders
- SMTP settings (host, port, username, password_enc, secure_tls) — For email delivery

### Existing Dependencies
- PHPMailer (via `src/utils/mailer.php`)
- PDO with MySQL
- Dompdf (for PDF rendering)
- Composer autoloader

### New Cron Schedule Required

**Option A: Separate cron for reminders** (recommended)
```bash
# Run reminders cron daily at 9 AM
0 9 * * * /usr/bin/php /var/www/src/cron/send_invoice_reminders.php >> /var/log/project_alpha/cron.log 2>&1

# Run main cron (invoices + optional reminders) daily at 10 AM
0 10 * * * /usr/bin/php /var/www/src/cron/generate_recurring_invoices.php >> /var/log/project_alpha/cron.log 2>&1
```

**Option B: Keep embedded in main cron**
- `generate_recurring_invoices.php` already includes reminders logic
- Executes after invoice generation if either setting is enabled
